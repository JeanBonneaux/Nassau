## Q1 — Quels projets existent ? (catalogue)

### Takeaway
Il existe des dizaines de projets, presque tous fondés sur le port série mini-DIN 7 broches (Open Interface) : (a) la lignée ESP8266/MQTT (johnboiles, The Hook Up ESP-01, incmve…) de 2016-2020 ; (b) la lignée ESPHome (mannkind → davidecavestro → wburgers → philpownall → ShonP40 « ESPRoomba », toujours active en 2025) ; (c) des projets Raspberry Pi (souvent avec caméra) ; (d) quelques ESP32/ESP32-CAM récents. **Aucun n'est documenté sur un Roomba 694** ; les modèles « proches » réellement utilisés sont le 690 (Pi / câble FTDI), le 671, le 650, le 655, le 630/632, le 620/621, le 605, le 615/652 ; le seul 692 trouvé est un échec non expliqué.

### Inferences
- [non confirmé] Pour un 694, la base logicielle la plus vivante et la mieux outillée pour Home Assistant est la lignée ESPHome (ShonP40/ESPRoomba, ESPHome 2025.11+), mais elle n'annonce que « 600 series » sans numéro ; la base la mieux « prouvée » sur un modèle Wi-Fi de la même génération est le côté Raspberry Pi / USB-série (690 : KieranK07, process1183).
- [non confirmé] La quasi-totalité des projets ESP antérieurs à 2020 ont été validés sur des 5xx/650/7xx/8xx à carte mère ancienne ; leurs leçons sur les niveaux logiques ne se transposent pas forcément aux cartes STM32 plus récentes (voir Q3, Roomba 616).

## Q2 — Existe-t-il une confirmation explicite sur Roomba 694 ? Sur 692, 675 ou 690 ?

### Takeaway
**Non pour le 694** : aucune source trouvée (GitHub, forum HA jusqu'au post n°298, hackaday, blogs, recherche web EN/FR) ne rapporte un ESP/Pi/Arduino branché sur le port série d'un 694. **Oui pour le 690** (modèle Wi-Fi de la même famille), via câble FTDI et via Raspberry Pi. **692** : un seul essai, en échec non expliqué. **675** : rien. Le 671 a fonctionné avec un Pi.

### Cited Findings
- [694 confirmé — mais hors série] Les seules mentions explicites du 694 concernent le Wi-Fi local, pas le port série : « Mac app to start, pause, and dock a Roomba 694 on the local network » ([mikey-dev404/roomba-controller](https://github.com/mikey-dev404/roomba-controller), description GitHub, pushed 2026-10-01) ; « The Roomba 694 (firmware 3.5.18) is one » ([roombapy #624](https://github.com/pschmitt/roombapy/issues/624), 2026-11-07) — voir Hors périmètre.
- [autre modèle: 690] « **The 690 speaks the full Open Interface over serial.** This mattered because the 690 is a Wi-Fi model, and community reports are ambiguous about whether Wi-Fi 600-series units (690/675) retain OI. ## Q3 — Détails matériels : alimentation, 5 V → 3,3 V, RX du robot, BRC, schémas

### Takeaway
Montage type : régulateur (buck) alimenté par Vpwr (broches 1-2) → 3,3 V ou 5 V pour l'ESP ; TX de l'ESP direct sur la broche 3 (RXD robot) ; TX du robot (broche 4) vers RX de l'ESP via **diviseur** (5 k/10 k, 2 k/1 k…) **ou transistor PNP** (2N3906 / 2N2907A / 2N4403, recommandé par un document iRobot cité par mannkind) **ou** convertisseur de niveaux (résultats contradictoires) ; une GPIO sur BRC (broche 5) tirée à la masse par impulsions pour réveiller. Pour un Pi : adaptateur USB-série (CP2104, FTDI) ou HAT avec convertisseur de niveaux, et alimentation 5 V par UBEC/buck. Les broches 1-2 passent par un **fusible PTC de 200 mA** (cité par trois sources).

## Q4 — Pièges rapportés

### Takeaway
Les problèmes récurrents sont, dans l'ordre : (1) **robot qui s'endort / ne se réveille plus sur la base** (650 de 2016+ surtout) et contournements imparfaits (nettoyages fantômes, relais sur CLEAN, LED IR) ; (2) **décharge de la batterie et charge coupée** si l'on laisse le robot en Safe/Full ou si l'on le maintient éveillé ; (3) **niveaux logiques** (diviseur qui ne marche pas, convertisseurs aux fronts trop lents, ESP ou port OI détruits) ; (4) **alimentation** (fusible PTC 200 mA, régulateur linéaire qui chauffe, brown-outs pendant que les moteurs tournent) ; (5) **UART** de l'ESP8266 partagé et données parasites au redémarrage du robot.
